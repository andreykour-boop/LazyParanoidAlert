# Proposal: add-boot-events

## Why

Агент молчит о перезагрузках машины: владелец узнаёт о включении сервера или десктопа только косвенно (по алертам о старте ловушек в логах, которых в Telegram нет). Для honeypot-агента «машина включилась не по плану» и «прошлое завершение было аварийным» — события того же класса важности, что и входы: их нужно доставлять в Telegram немедленно и с классификацией.

## What Changes

- Новый датчик `boot` в конвейере агента: при старте сравнивает идентификатор загрузки машины с сохранённым (`data/boot.json`); совпадение = рестарт службы (молча), отличие = новая загрузка машины.
- При новой загрузке — немедленный алерт (direct-канал доставки, мимо окна агрегации) с классификацией прошлой сессии: штатное завершение или аварийное, инициатор, действие (перезагрузка vs выключение→включение), длительность простоя.
- Windows: источник фактов — System-канал журнала событий (1074 — инициатор/причина/действие, 6006/6008/41 — штатность); исторический запрос `EvtQuery` вместо подписки (System-канал не требует Event Log Readers).
- Linux: источник фактов — хвост предыдущей загрузки `journalctl -b -1` (маркер `Reached target Reboot/Power-Off` — штатность, sudo-строка — инициатор; инициатор best-effort).
- Обе платформы: датчик всегда включён, без ключа конфига (как двери).
- Первый запуск (нет файла состояния) — записать идентификатор молча, без алерта.

## Capabilities

### New Capabilities

- `boot-events`: отчёт о загрузке машины: детект новой загрузки с защитой от ложных срабатываний на рестарт службы, классификация предыдущей сессии (штатно/аварийно, инициатор, действие), немедленная доставка в Telegram на обеих платформах.

### Modified Capabilities

(нет — двери, ловушки и доставка не меняются; датчик встраивается рядом)

## Impact

- `cmd/siren/runtime.go` — новый one-shot-компонент `boot` в конвейере (рядом с `runDoors`).
- `cmd/siren/doors_windows.go` / `doors_linux.go` — платформенные развилки получат соседа `boot_windows.go` / `boot_linux.go`.
- `internal/doors/winlog_windows.go` — добавляется `EvtQuery` (исторический запрос) к существующему `EvtSubscribe`; System-канал читается без элевейшна.
- `internal/event` — новый Kind (`machine_boot`).
- `internal/notify` — текст алерта о загрузке (плюс маска «сводка»).
- `data/boot.json` — новое состояние (идентификатор загрузки); формат тривиален, деградация при потере — один пропущенный алерт.
- Конфиг не меняется; панель не меняется.
