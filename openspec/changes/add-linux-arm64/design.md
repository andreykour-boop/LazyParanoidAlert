# Design: add-linux-arm64

## Context

Сборка — `build.ps1` (windows/amd64 через rsrc-манифест + linux/amd64,
`CGO_ENABLED=0`). Код чисто-Go: платформенные вещи — `syscall`/`exec`
(journalctl, PowerShell, wevtapi), зависимостей от архитектуры нет; пробная
сборка `linux/arm64` и `windows/arm64` проходит без правок кода. Комплекты
лежат в gitignored `dist/`; канонические исходники кита разрознены:
`siren.service` — в `deploy/`, `config.example.json` — в корне репо,
`install.sh`/`uninstall.sh` — только в dist (в репо отсутствуют).
WSL/Docker на рабочей машине нет — arm64-рантайм проверяется только на
реальном железе. Релиз v0.4.0 не опубликован (GitHub-аккаунт заблокирован),
поэтому переименование артефактов ничего не ломает.

## Goals / Non-Goals

**Goals:**

- Сборка `linux/arm64` наравне с остальными, из той же `build.ps1`.
- Имена артефактов с явной архитектурой: bin, каталоги китов, zip.
- Кит arm64 идентичен amd64-киту по составу и поведению установки.
- Консолидация исходников кита в репо (`deploy/`), чтобы кит собирался
  воспроизводимо, а не из неконтролируемых копий в dist.

**Non-Goals:**

- Windows ARM64 (отклонено: walk-пульт в рантайме не обкатан; эмуляция
  amd64 в Windows on ARM покрывает сценарий; вернуться при наличии железа).
- 32-битный ARM (armv7) — только 64-бит.
- Изменения runtime-кода, конфига и спеков.
- Публикация релиза v0.4.0 (ждёт разблокировки GitHub; zip будут готовы).

## Decisions

- **D1: фиксированная матрица трёх целей в `build.ps1`, без параметра
  `-Arch`.** Сборка занимает секунды; параметр — гибкость, которой никто не
  просил. windows/amd64 — как сейчас (rsrc `.syso`), linux/amd64 и
  linux/arm64 — статические бинарники `bin/siren-linux-{amd64,arm64}`.
- **D2: явная архитектура во всех именах.** `dist/siren-windows-amd64-kit/`
  (бывш. siren-win-kit), `dist/siren-linux-amd64-kit/` (бывш.
  siren-linux-kit), новый `dist/siren-linux-arm64-kit/`; zip — те же имена.
  `bin/` уже суффиксирован. Релиз v0.3 остаётся историческим со старыми
  именами; README и доки обновляются в этом же change.
- **D3: `install.sh`/`uninstall.sh` — канонически в `deploy/`, в кит
  копируются при сборке.** Проверка архитектуры: переменная
  `EXPECTED_ARCH="x86_64"|"aarch64"` в шапке каждого экземпляра (по киту),
  `uname -m` сверяется с ней, несоответствие — fail-fast с понятным
  сообщением. Один шаблон, две готовые копии — без скриптовой магии.
- **D4: сборка китов — вручную тем же порядком, что сейчас** (копирование
  бинарника + статических файлов в dist-каталог, zip через Compress-Archive);
  `make-release.ps1` во временных скриптах — обновить имена. Отдельный
  pack-скрипт в репо — не в этом change (когда релиз разблокируется,
  процедура и так отработана).
- **D5: arm64-кит = amd64-кит по содержанию.** Тот же `config.example.json`
  (профиль server), тот же юнит (`CAP_NET_BIND_SERVICE`,
  `SupplementaryGroups=systemd-journal`), те же ожидания от установки.
  Сторож здоровья на железе без SMART честно репортит отсутствие
  инструментов — поведение уже в спеке disk-health-watch.

## Risks / Trade-offs

- [Нет локального arm64-рантайма (WSL/Docker отсутствуют)] → компиляция и
  `go vet` дают уверенность в типах, но не в поведении; живая проверка —
  отдельной задачей на реальном ARM-железе владельца, до неё фича считается
  непроверенной вживую.
- [Переименование kit-zip ломает ссылки в опубликованном релизе v0.3] →
  v0.3 исторический; v0.4.0 публикуется с новыми именами и обновлённым
  README; кому нужен старый релиз — старые ссылки живут в теге.
- [rsrc `-arch arm64` experimental] → не используется: windows/arm64 не
  собираем, манифест остаётся только для amd64.
- [SSH-баннер ловушки рекламирует «x86_64» на ARM-хосте] → фикстура-декой,
  правка вне скоупа; зафиксировано как известная косметика.
