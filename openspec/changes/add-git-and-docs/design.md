# Design

## Context

См. proposal.md. Проект не git-репозиторий; документация существует фрагментарно (`dist/*/README.txt`, `deploy/`), секреты лежат в живом каталоге `agent/`. Публикация — публичный GitHub, что повышает требования к чистоте содержимого и истории.

## Goals / Non-Goals

**Goals:**
- Репозиторий, который можно публиковать одной командой push, без секретов и личных файлов.
- Документация, покрывающая установку, все параметры конфига и архитектуру.
- Единый источник правды: дока не дублирует спеки, а ссылается на них.

**Non-Goals:**
- Изменение поведения агента (Go-код, конфиги, сборка не трогаются, кроме тестовых фикстур — см. D2).
- CI/CD, релизы, GitHub Actions — можно добавить позже.
- Английская версия доки.

## Decisions

- **D1: `.gitignore` — игнорировать целые каталоги, а не выборочные файлы.** `agent/` (секреты, логи, exe, state), `bin/`, `dist/` (сборочные артефакты, пересобираются `build.ps1`), плюс точечно: `*.log`, `*.exe`, `*.exe~`, `*.syso`, `opencode.json`, `AGENTS.md`, `.opencode/`. Игнорировать каталоги целиком надёжнее точечных списков: новый лог или дамп в `agent/data/` не попадёт в коммит по оплошности. Личные файлы OpenCode тоже в игноре — они рабочие локально, но в публичный репо не входят.

- **D2: тестовые фикстуры чистятся от следов реальной сети.** В `internal/notify/format_disk_test.go` фигурируют `192.168.11.26` и `DESKTOP-4FCDLB0` (реальная машина). Замена на зарезервированные для документации адреса (RFC 5737: `192.0.2.x`) и нейтральное имя (`TEST-PC`). Поведение не меняется, тесты прогоняются заново. В `openspec/` реальные IP не встречаются (проверено grep), модели дисков (TOSHIBA и т. п.) — не идентифицирующие, остаются.

- **D3: документация — README.md + docs/, на русском.** README — обзор и быстрый старт (установка из китов за 4 шага), детали — в `docs/`: `architecture.md` (конвейер, ловушки/двери, агрегация, allowlist-семантика, сторож здоровья), `configuration.md` (все параметры `config.json` с примерами), `deployment.md` (обе платформы, обновление, проверка, эксплуатация `-health-report`, пульт). Альтернатива «всё в одном README» отвергнута: параметров много, файл стал бы нечитаемым.

- **D4: примеры — вымышленные.** IP из документационных диапазонов (203.0.113.0/24, 192.0.2.x), имена машин `TEST-PC`/`SRV-02`, токены вида `123456:AA...`-плейсхолдеры. Примеры алертов — текстовые блоки, без скриншотов (реальные скриншоты содержат IP внутренней сети).

- **D5: git — один начальный коммит на ветке `main`, затем push.** `git init -b main`, первый коммит — всё разом (код, спеки, дока, LICENSE, .gitignore). История с нуля, ничего «доигрывается» задним числом. Пульт `https://github.com/kur890440-ops/siren`; аутентификация push — через Git Credential Manager (браузер-вход), либо владелец выполняет push сам.

## Risks / Trade-offs

- [Секрет просочится в первый коммит] → `.gitignore` (D1) + перед коммитом контрольный `git status` и grep по индексу на токен-паттерны; каталог `agent/` игнорируется целиком.
- [Дока разойдётся с кодом] → в `docs/configuration.md` значится источник: спеки `openspec/specs/` — поведение, конфиг-примеры — формат; расхождение правится в том же change, что и поведение.
- [Публичность раскрывает детали защиты] → ловушки и семантика allowlist документируются, но без данных о реальном размещении агентов; все адреса вымышленные (D4).

## Migration Plan

1. Файлы: `.gitignore`, `LICENSE`, `README.md`, `docs/*.md`, правка фикстур (D2) — тесты зелёные.
2. `git init -b main`, добавить всё кроме игноров, контрольный осмотр `git status`, коммит.
3. Push на GitHub (репозиторий создаёт владелец пустым; я делаю push или даю команду владельцу).
4. Откат — тривиален: удаление репозитория/каталога `.git` не затрагивает рабочие файлы.
