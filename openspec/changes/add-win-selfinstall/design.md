# Design

## Context

См. proposal.md. Обследование кода: `service_windows.go` умеет install/remove/start/stop, но не знает о firewall (0 упоминаний); первый запуск открывает панель с состоянием «не установлена» и ошибкой отсутствующего конфига; self-copy и бутстрап конфига отсутствуют — их делает только `install.ps1`. Панель уже умеет: ввод токена с валидацией и «Сохранить и перезапустить», «Установить и запустить», «Удалить», single-instance.

## Goals / Non-Goals

**Goals:**
- Один exe решает всё: скачать → запустить → ввести токен → работает.
- Firewall-правило — часть жизненного цикла службы, а не скрипта.
- Повторный запуск = обновление установленной копии.

**Non-Goals:**
- Linux (install.sh остаётся как есть).
- Автообновление по сети, подписи/сертификаты, self-uninstall файла.
- Изменение формата конфига и конвейера агента.

## Decisions

- **D1: Триггер самоустановки — интерактивный запуск при `служба не установлена`.** Проверяется до открытия панели. Самокопирование выполняется всегда, когда текущий путь exe отличается от `%ProgramFiles%\siren\siren.exe` (первый запуск или обновление); затем перезапуск себя оттуда с теми же флагами. Если exe уже лежит в `%ProgramFiles%\siren`, но службы нет — копирование пропускается, ставится служба. Headless-режимы (`-console`, `-service`, `-health-report`) самоустановку не триггерят — только интерактивный запуск с панелью.

- **D2: Обновление — через ту же ветку self-copy.** Если служба установлена и работает с пути `%ProgramFiles%\siren\siren.exe`, а запущен другой exe: служба останавливается (best-effort, ожидание), копия заменяется, служба стартует заново. Признак «другой exe» — сравнение размера+времени модификации недостаточно надёжно: используем сравнение бинарников (или версии из ресурса при расхождении — сравнение побайтовое простое и достаточное для файла ~10 МБ).

- **D3: Бутстрап конфига — встроенный шаблон (`go:embed`).** В `cmd/siren` встраивается шаблон (копия `config.example.json` с плейсхолдерами); при создании `agent_name` подставляется из hostname. Существующий конфиг никогда не перезаписывается. Плейсхолдер токена — сигнал «службу не запускать» (существующая конвенция install.ps1, переносится в код).

- **D4: Firewall — `netsh advfirewall firewall` из кода установки службы.** Правило программное (по пути exe), входящий TCP, displayName «siren traps». Создание — в `serviceInstall`, удаление — в ветке `remove`; идемпотентность — предварительный запрос существующего правила (`netsh advfirewall firewall show rule name=...`) и при совпадении пути — пропуск; при другом пути — замена (delete+add). Выбор netsh против COM API (INetFwPolicy2) и PowerShell-кмдлетов: netsh есть на всех поддерживаемых Windows, не требует CGO/реестровых хаков, вывод парсится тривиально. Правило привязано к программе, а не к порту — порт-набор меняется конфигом без правки firewall.

- **D5: Порядок первого запуска.** UAC (manifest) → self-copy/обновление → бутстрап конфига → install службы (внутри — firewall) → start, если токен реальный → панель. Панель показывает состояние «установлена, не запущена — нужен token» и штатную кнопку «Сохранить и перезапустить» для ввода токена. Кнопка «Установить и запустить» остаётся как ручной путь восстановления, ведёт к тому же коду установки.

- **D6: Кит и репозиторий.** `dist/siren-win-kit/` = только `siren.exe` (+ README-выжимка не нужна: доки в репо); `deploy/install.ps1`, `deploy/uninstall.ps1` удаляются. README и `docs/deployment.md` переписываются под сценарий одного exe; acceptance-чеклист Windows в `deploy/acceptance.md` правится под новый сценарий.

## Risks / Trade-offs

- [Self-copy при занятом файле (служба работает из целевого пути)] → остановка службы перед копированием с ожиданием; запуск не из целевого пути не держит файл.
- [netsh-парсинг хрупок между версиями Windows] → идемпотентность через `show rule` с проверкой кода возврата и текста; при неудаче — предупреждение в журнал и сообщение панели, установка службы не срывается (fail-open: без правила агент работает локально, ловушки видны только с хоста).
- [Пользователь запускает exe как «обновление», но версия та же] → побайтовое сравнение пропускает лишний restart службы; критерием не становится «версия в строке», которую легко забыть поднять.
- [Первый запуск без токена оставляет установленную неработающую службу] → осознанно: панель сразу показывает, чего не хватает; состояние «установлена, не запущена» видно и в SCM.

## Migration Plan

1. Код: self-copy/bootstrap (D1–D3), firewall в install/remove (D4), склейка порядка запуска (D5) — тесты на каждую единицу.
2. Кит и доки (D6), удаление ps1.
3. Полная сборка + прогон тестов; живая проверка на Windows-машине владельца: чистый запуск из Downloads → токен → алерт.
4. Откат: код реверсится, ps1 возвращаются из истории git (репозиторий уже в git).
