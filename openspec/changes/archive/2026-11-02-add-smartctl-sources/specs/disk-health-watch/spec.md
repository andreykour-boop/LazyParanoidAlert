# Spec Delta

## MODIFIED Requirements

### Requirement: Счётчики секторов SMART в снимке L1

Снимок L1 SHALL включать для каждого физического диска доступные счётчики здоровья: realloc и pending для ATA/SATA-дисков; media errors (Media and Data Integrity Errors) и wear (Percentage Used, %) для NVMe-дисков. Счётчики SHALL собираться утилитой smartctl, когда она доступна на машине; на Windows при недоступности smartctl счётчики SATA SHALL собираться из SMART-данных WMI (`root\wmi\MSStorageDriver_FailurePredictData`) как фолбэк. Диск, для которого ни один источник не отдаёт счётчики (USB-мост, контроллер без прокидывания SMART), MUST NOT порождать ошибку источника и MUST показываться как прежде — без счётчиков. Отчёты и панель SHALL показывать счётчики рядом со статусом диска, когда они собраны.

#### Scenario: SATA-диск Windows со счётчиками

- **WHEN** сторож собирает снимок на Windows-машине с SATA-диском и установленным smartctl
- **THEN** запись этого диска в отчёте и панели содержит realloc и pending, например «sda: ok — realloc 0, pending 0», с честными raw-значениями

#### Scenario: NVMe-диск со счётчиками

- **WHEN** сторож собирает снимок на машине с NVMe-диском и установленным smartctl
- **THEN** запись этого диска содержит media errors и wear, например «nvme0n1: ok — media errors 0, wear 11%»

#### Scenario: Диск без счётчиков

- **WHEN** счётчики для диска недоступны ни от одного источника (USB-диск с мостом без прокидывания SMART)
- **THEN** диск показывается со статусом без счётчиков, секция «не смог проверить» не пополняется

#### Scenario: smartctl не установлен на Windows

- **WHEN** на Windows-машине smartctl отсутствует, а SATA-диск прокидывает SMART в WMI
- **THEN** счётчики SATA собираются через WMI-фолбэк; отсутствие smartctl само по себе не попадает в секцию «не смог проверить»

## ADDED Requirements

### Requirement: Тревога на рост media errors NVMe

Сторож SHALL отправлять немедленную тревогу в Telegram при увеличении media errors любого NVMe-диска между предыдущим и текущим снимками, даже если статус диска остаётся «ok». Тревога MUST содержать имя диска, предыдущее и новое значения. При неизменном значении или при первом снимке тревога MUST NOT отправляться.

#### Scenario: Media errors выросли

- **WHEN** в предыдущем снимке NVMe-диск имел media errors 0, в текущем — 3
- **THEN** в чат приходит тревога с именем диска и значениями «0 → 3», вне расписания отчётов

#### Scenario: Media errors не изменились

- **WHEN** media errors NVMe-диска одинаковы в предыдущем и текущем снимках, либо предыдущего снимка нет
- **THEN** тревога не отправляется, диск отображается с текущими значениями

### Requirement: Перебазирование счётчиков при смене источника

Когда счётчики диска в текущем снимке получены от другого источника, чем в предыдущем, агент MUST NOT порождать тревогу на основе разницы значений между ними: счётчик SHALL перебазироваться, как при первом снимке. Смена источника сама по себе не является изменением здоровья диска и MUST NOT порождать тревогу или запись в секции «не смог проверить».

#### Scenario: Источник счётчиков сменился

- **WHEN** в предыдущем снимке счётчики диска собраны одним источником (значение 100), в текущем — другим (значение 0), при неизменном состоянии диска
- **THEN** тревога роста не отправляется, счётчики нового источника фиксируются как новая база

#### Scenario: После перебазирования реальный рост ловится

- **WHEN** после смены источника счётчик монотонного счётчика деградации вырос на 1
- **THEN** тревога отправляется на основе базы нового источника
