# Proposal

## Why

В доверенной локальной сети (Windows-машины с RDP, Linux с SSH, домен AD) отсутствует раннее оповещение о чужой активности: попытках входа, подключениях к незадействованным портам и сканировании. Нужна лёгкая утилита-«сирена», которая сама замечает такие события и сообщает о них в Telegram, не выдавая себя наблюдаемому атакующему.

## What Changes

- Добавляется кроссплатформенный агент-сирена (один код для Windows и Linux), запускаемый как служба Windows / systemd-юнит.
- Агент открывает «ловушки» на настраиваемых портах, не занятых реальными сервисами, и правдоподобно эмулирует ответы соответствующих протоколов (SSH-баннер, HTTP, FTP, VNC и т.д.), чтобы подключившийся не понял, что его зафиксировали.
- Агент читает факты попыток и успешных входов на занятых портах: RDP на Windows (события 4625 / 4624 type 10 / 1149) и SSH на Linux (journald: Failed/Accepted password).
- Каждый факт подключения обогащается: IP источника -> hostname (reverse DNS), MAC (ARP), опционально ручная карта IP -> имя в конфиге.
- События агрегируются (брутфорс и сканирование не должны породить сотни сообщений) и доставляются в Telegram через bot API.
- Ловушки и датчики дверей включаются/отключаются индивидуально по портам в конфиге; набор портов по умолчанию учитывает роль машины (desktop / server) и фоновые порты доверенной сети (SMB 445/135/139, доменные службы 53/88/389/464) исключены из датчиков.

## Capabilities

### New Capabilities

- `port-traps`: прослушивание настраиваемых портов-ловушек с эмуляцией протоколов; фиксация факта подключения с IP источника; индивидуальное включение/отключение по портам.
- `auth-event-monitoring`: сбор фактов попыток входа (неудачных) и успешных входов по RDP (Windows) и SSH (Linux) с указанием IP источника и учётной записи.
- `alert-delivery`: обогащение событий (hostname, MAC), агрегация повторяющихся событий и доставка уведомлений в Telegram с учётом лимитов API.

## Impact

- Новый код: один бинарник (Go) с двумя целевыми платформами (windows/amd64, linux/amd64).
- Развёртывание: служба Windows под учёткой с правом чтения журналов (Event Log Readers) / systemd-юнит в группе `systemd-journal` с `CAP_NET_BIND_SERVICE` (порты <1024 на Linux).
- Внешние зависимости: Telegram Bot API (исходящий HTTPS); токен бота в локальном конфиге.
- Не входит в объём: инспекция полезной нагрузки трафика, журналы файрвола/аудит WFP, ловушки на портах, занятых реальными сервисами, детект по drop-логам.
