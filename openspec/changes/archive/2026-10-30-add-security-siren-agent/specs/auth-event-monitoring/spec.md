# Spec Delta

## Purpose

Сбор фактов неудачных попыток входа и успешных входов на портах с реальными сервисами: RDP на Windows (события Security и RemoteConnectionManager) и SSH на Linux (journald). Каждое событие содержит IP источника и учётную запись, когда она известна.

## ADDED Requirements

### Requirement: Факт неудачной попытки входа по RDP

Система SHALL формировать событие «попытка входа» для каждого неудачного входа по RDP (Logon Type 10) на Windows-машине, содержащее учётную запись, которую пытались использовать, время и IP источника, если он присутствует в событии.

#### Scenario: Неудачный вход по RDP фиксируется

- **WHEN** в журнале Security появляется событие 4625 с Logon Type 10
- **THEN** формируется событие «попытка входа RDP» с учётной записью, временем и IP источника, если он есть в событии

### Requirement: Факт успешного входа по RDP

Система SHALL формировать событие «вход» для каждого успешного входа по RDP (Logon Type 10) на Windows-машине, содержащее учётную запись, время и IP источника.

#### Scenario: Успешный вход по RDP фиксируется

- **WHEN** в журнале Security появляется событие 4624 с Logon Type 10
- **THEN** формируется событие «вход RDP» с учётной записью, временем и IP источника

### Requirement: Факты входа по SSH

Система SHALL формировать события «попытка входа» и «вход» по SSH на Linux-машине из записей journald юнита ssh: неудачные попытки (Failed password, включая invalid user) и успешные входы (Accepted password, Accepted publickey), каждая с IP источника, учётной записью и временем.

#### Scenario: Неудачная попытка SSH фиксируется с подставленной учёткой

- **WHEN** journald содержит запись «Failed password for invalid user admin» с IP источника
- **THEN** формируется событие «попытка входа SSH» с учётной записью «admin», IP источника и временем

#### Scenario: Успешный вход SSH фиксируется

- **WHEN** journald содержит запись «Accepted publickey for andrey» с IP источника
- **THEN** формируется событие «вход SSH» с учётной записью «andrey», IP источника и временем

### Requirement: Событие без IP не теряется

Если источник события не содержит IP (например, локальный вход), система SHALL сформировать событие с явной пометкой об отсутствии IP, а не пропускать его.

#### Scenario: Событие 4625 без IP помечается

- **WHEN** событие неудачного входа не содержит IP источника
- **THEN** событие формируется с учётной записью и временем, а поле источника помечено как неизвестное

### Requirement: Нераспознанные записи журнала сохраняются для диагностики

Система SHALL записывать в собственный журнал записи источника, не соответствующие известным шаблонам, чтобы их можно было учесть при донастройке парсера, и SHALL NOT молча отбрасывать их.

#### Scenario: Нестандартная строка journald попадает в журнал агента

- **WHEN** запись journald юнита ssh не соответствует ни одному известному шаблону входа
- **THEN** агент сохраняет её текст в собственный журнал диагностики
