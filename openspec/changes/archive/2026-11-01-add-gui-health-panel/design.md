# Design

## Context

Сторож дисков (`internal/health`) работает внутри конвейера агента: Runner по расписанию собирает снимок через коллекторы и атомарно пишет его в `DataDir/health_state.json` (`SaveState`, tmp+rename). Пульт (`cmd/siren/ui_windows.go`, walk) при работающей службе конвейер не запускает — он только управляет службой, IPC между процессами нет; единственный мост — файл снимка. Служба при старте делает `Chdir(filepath.Dir(exe))`, поэтому относительный `data_dir` она разрешает от каталога exe. Готовые кирпичи: `health.LoadState`, `health.Collector.Snapshot`, `health.NewPlatformSources` (только Windows), рендер `health.WeeklyReport`.

## Goals / Non-Goals

**Goals:**

- Секция «Диски» в окне пульта: снимок из `health_state.json`, время сбора и возраст, тома, диски L1, источники-ошибки, выделение томов ниже порога.
- «Проверить сейчас»: живой сбор в процессе пульта, без записи состояния и без Telegram.
- Понятные состояния: «сторож выключен», «снимка нет», «снимок устарел».

**Non-Goals:**

- Изменение поведения службы, расписаний, конфига (включая схему `health`) — только чтение.
- IPC с работающей службой (не нужен: файл снимка достаточен).
- Цветовая индикация иконки трея по состоянию дисков (отдельная будущая фича).
- Linux: пульт существует только в windows-сборке.

## Decisions

**D1. Источник — файл снимка, путь разрешается от каталога exe.**
Пульт читает `health_state.json` через `health.LoadState`. Относительный `DataDir` пульт разрешает от `filepath.Dir(os.Executable())` — так же, как служба делает `Chdir(filepath.Dir(exe))` при старте. Абсолютный `DataDir` из конфига используется как есть. Альтернатива (резолв от каталога конфига) отклонена: она совпадает с каталогом exe только в текущей раскладке установки и разъедется, если конфиг положат отдельно.

**D2. Рендер панели — собственный, телеграм-отчёт не трогаем.**
Формат панели отличается от еженедельного отчёта по решению владельца (обратная связь с живого запуска): сначала диски SMART, затем (при наличии) массивы/пулы, затем тома построчно «всего / занято / свободно», затем секция «не смог проверить»; секции с пустыми данными (массивы) в панели не печатаются. Отчёт для Telegram остаётся на `health.SnapshotText` с его спечённым форматом («свободно» в ГБ и %). Тело отчёта вынесено в `SnapshotText`; панель рендерит через собственный `renderPanelBody` — дублирования формата нет, у каждого носителя свой контракт. Строки панели отдаются с `\r\n` (Windows EDIT control не ломает строки по `\n`).

**D3. Выделение предупреждений — текстовые метки, не цвета.**
walk не даёт раскрашивать отдельные строки Label/TextEdit; том ниже порога помечается меткой в строке (как в Telegram-алерте). Урок ловушек (`ui_windows.go`: динамические виджеты ненадёжны) подтверждает выбор простого статичного текстового блока: секция — GroupBox + read-only TextEdit, виджеты создаются один раз при `build()`, данные обновляются `SetText`.

**D4. Живая проверка — только чтение, вне конвейера.**
Кнопка запускает горутину: `health.NewPlatformSources()` → `Collector.Snapshot()` → рендер → `mw.Synchronize(SetText)`. `SaveState` не вызывается, notifier недоступен — сохранённый снимок и рассылка не затрагиваются даже при параллельной плановой проверке службы (обе стороны только читают железо; файл никто не трогает). На время сбора кнопка disabled с текстом «проверяю…»; ошибка — в текст панели.

**D5. Обновление: открытие окна + кнопка + таймер 60 с.**
Горутина-таймер тикает, пока окно видно (`mw.Visible()`), и через `mw.Synchronize` перечитывает файл. Перечитать файл дешевле, чем отслеживать изменения; 60 с достаточно для данных, меняющихся раз в сутки.

**D6. Порог устаревания — 26 часов.**
При `health.enabled` и возрасте снимка больше 26 ч (суточный цикл + запас) шапка помечает «снимок устарел» — это честный сигнал, что служба со сторожем давно не собирала данные (например, служба стоит), без ложной тревоги сразу после пропуска одного чека.

## Risks / Trade-offs

- [Пульт и служба одновременно работают с одним файлом] → пульт только читает; `SaveState` атомарен (tmp+rename), частичного чтения не бывает; живая проверка пульта файл не пишет по построению.
- [Живая проверка идёт секунды (WMI/smartctl)] → кнопка блокируется на время сбора, статус «проверяю…»; повторные клики не наслаивают горутины.
- [Снимок службы собирается только при старте службы и в 09:00] → шапка всегда показывает время сбора и возраст; кнопка живой проверки закрывает потребность в «свежем» без ожидания расписания.
- [Конфиг не читается (`cfgErr`)] → секция показывает «конфиг не читается: …», окно остаётся пригодным для остального управления (существующее поведение msgLabel сохраняется).

## Migration Plan

Аддитивное изменение GUI без данных и конфига: пересборка exe → стандартный путь обновления (`install.ps1` / остановка службы, замена бинарника, старт). Откат — вернуть прежний бинарник; состояние и конфиг не меняются.
