# Spec Delta

## ADDED Requirements

### Requirement: Разрешённые источники (allowlist)

Система SHALL подавлять доставку событий от источников из allowlist конфига: IP или CIDR-сеть с необязательным суффиксом портов. Запись без портов подавляет все события источника; запись с портами — только события перечисленных портов (ловушки на них и реальные входы по сервису порта: SSH — 22, RDP — 3389). События без привязки к порту и события других портов SHALL доставляться как прежде. Источник вне allowlist и источник с неизвестным IP MUST NOT подавляться.

#### Scenario: Запись без портов глушит источник целиком

- **WHEN** allowlist содержит «192.168.1.10» и этот хост подключается к любой ловушке
- **THEN** событие не доставляется в Telegram

#### Scenario: Запись с портом глушит только этот порт

- **WHEN** allowlist содержит «192.168.1.10:22», хост подключается к ловушке на порт 22 и затем к ловушке на порт 23
- **THEN** событие по порту 22 не доставляется, событие по порту 23 доставляется как тревога

#### Scenario: Реальный вход по разрешённому сервису подавляется

- **WHEN** allowlist содержит «192.168.1.10:22», хост успешно входит по SSH на машину с реальным sshd на порту 22
- **THEN** событие входа не доставляется, при этом его попытка входа с этого же хоста к другой ловушке остаётся видимой

#### Scenario: Событие без порта не подавляется записью с портами

- **WHEN** allowlist содержит запись с портами, а источник события не привязан к сервисному порту (порт события неизвестен)
- **THEN** событие доставляется как прежде

#### Scenario: Сеть с портами

- **WHEN** allowlist содержит «10.0.0.0/24:22,3389», хост из этой сети подключается к ловушке на порт 3389 и к ловушке на порт 5900
- **THEN** событие по порту 3389 не доставляется, событие по порту 5900 доставляется

### Requirement: Формат allowlist-записей

Конфигурация SHALL принимать allowlist-записи формата «IP[/CIDR]» с необязательным суффиксом «:порт[,порт…]» (порты 1–65535); для IPv6-адреса с портами — скобочная форма. Записи вне формата MUST отклоняться валидацией конфига с указанием номера записи.

#### Scenario: Некорректная запись отклоняется

- **WHEN** в конфиге allowlist содержит строку, не являющуюся IP, CIDR или записью «хост:порты» в допустимом формате
- **THEN** загрузка/сохранение конфига завершается ошибкой валидации с указанием номера записи

#### Scenario: IPv6-записи

- **WHEN** allowlist содержит «::1» и «[::1]:22»
- **THEN** обе записи принимаются: «::1» — адрес без портов (подавление всего источника), «[::1]:22» — запись с портом 22
