# Design

## Context

Allowlist живёт в конвейере событий: `doors/traps → raw → allowlist+enrich → aggregator → notifier → Telegram` (`cmd/siren/runtime.go`, `pumpEnrich`). Запись — строка IP/CIDR в `config.allowlist`; `allowlist.match(ip)` в `cmd/siren/runtime.go` глушит событие целиком по IP источника. События ловушек несут `DstPort` (`internal/trap`), события датчиков входов `internal/doors` порт не проставляют. Валидация allowlist — `internal/config/config.go` (`netip.ParsePrefix`/`ParseAddr` на каждую строку). Поле в панели — многострочный текстовый бокс (`cmd/siren/ui_windows.go`), читается и пишется через общий `config.Config`.

## Goals / Non-Goals

**Goals:**
- Точечный allow: запись с портами глушит только события этих портов, остальное от хоста остаётся видимым.
- Обратная совместимость: записи без портов работают как раньше; старые конфиги читаются без правок.
- Единый парсер формата для валидации конфига, матчера и панели.

**Non-Goals:**
- Разрешение по диапазонам портов (`22-25`) — список через запятую покрывает практические случаи.
- Разные allowlist для ловушек и датчиков — один список, семантика определяется наличием портов у записи.
- Поддержка нестандартных портов SSH/RDP в датчиках: фиксированная карта сервисных портов (SSH 22, RDP 3389).

## Decisions

**D1. Формат записи — суффикс портов на той же строке.** `192.168.1.10:22`, `10.0.0.0/24:22,3389`, IPv6 с портами — `[::1]:22`; без портов — как раньше. Альтернативы: отдельное поле-объект в конфиге (ломает формат и панель без выгоды), отдельный список `allowlist_ports` (дублирование источников, рассинхронизация). Разбор: строка режется по последнему `:` только если хвост — список чисел 1–65535, а голова парсится как IP/CIDR; IPv6 без скобок с хвостовым числом неоднозначен, поэтому правило — сначала пробуется цельная строка как IP/CIDR (старое поведение), и только при промахе — разбор суффикса. Так `::1` остаётся адресом, а `[::1]:22` — записью с портом.

**D2. Матчер принимает порт события.** `allowlist.match(ip, port)`; запись хранит префикс + множество портов (`nil` = все). Событие подавляется, если IP в префиксе и (порты записи пусты-означают-все или порт события в списке). `pumpEnrich` передаёт `ev.DstPort`. События с портом 0 (без привязки) записями с портами не матчятся — только записями без портов. Альтернатива — два отдельных матчера для ловушек и датчиков отклонена: дублирует логику и усложняет панель.

**D3. Датчики входов штампуют сервисный порт.** RDP-факты (4624/4625, RemoteConnectionManager) — `DstPort = 3389`; SSH-факты (journald) — `DstPort = 22`. Без этого «только ssh» не работает на Linux, где реальный sshd занимает порт 22 и ловушка на 22 не открывается — точечная запись нечему матчить. Карта фиксированная; нестандартные порты SSH — вне скоупа (записывается в README). Альтернатива — конфигурируемая карта сервисных портов отложена: усложняет конфиг без запроса владельца.

**D4. Парсер формата — одна функция в `internal/config`.** `ParseAllowlistEntry(string) (addr string, ports []int, err)` используется валидацией конфига, матчитером (`cmd/siren`) и, косвенно, панелью (она валидирует через сохранение конфига). Ошибка валидации сохраняет прежний стиль: `config: allowlist[i]: ...` с номером записи. Альтернатива — дублировать разбор в `cmd/siren` отклонена: расхождение валидатора и матчера даёт записи, которые «валидны, но не работают».

**D5. Матчер строится из валидированного конфига без повторного спора о синтаксисе.** `newAllowlist` принимает уже разобранные записи (строка + порты), а не сырые строки: конфиг валиден при загрузке и сохранении, поэтому матчер может доверять входу и лишь логировать аномалию (конфиг правлен на лету). Минимальное изменение текущего контракта.

## Risks / Trade-offs

- [Тихое подавление из-за опечатки в порту: «хост:2» вместо «хост:22» узко разрешает не то] → валидация отклоняет только структурный мусор; смысловую опечатку ловит ревью конфига в панели — записи с портами видны построчно; README приводит примеры.
- [SSH-факты со стандартным портом 22 на машине с нестандартным sshd не матчатся записью «:22»] → зафиксировано в Non-Goals и README; владелец может добавить запись без портов.
- [CIDR с портами расширяет подавление на всю сеть] → семантика явная («сеть:порты»), пример в README; запись без портов и раньше глушила сеть целиком.
- [Двойной разбор (валидатор, затем матчер) расходится, если конфиг правят на лету мимо валидации] → матчер логирует проигнорированную запись в журнал (как сейчас), событие остаётся видимым — fail-open в сторону видимости.

## Migration Plan

Конфиг читается тем же парсером: старые записи без портов валидны и работают как раньше; миграция не требуется. Откат — прежний бинарник читает записи с портами как невалидные и упадёт при загрузке конфига только если такая запись сохранена; перед откатом убрать записи с портами (панель или руками).
