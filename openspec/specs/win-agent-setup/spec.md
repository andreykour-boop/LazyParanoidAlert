# win-agent-setup Specification

## Purpose

Самоустановка Windows-агента: один exe при первом запуске сам размещает себя в системе, создаёт конфиг, ставит службу и открывает firewall, не требуя ни Go, ни скриптов установки.

## Requirements

### Requirement: Первый запуск выполняет самоустановку

Интерактивный запуск exe, при котором служба не установлена, SHALL выполнить самоустановку: разместить копию exe в `%ProgramFiles%\siren\siren.exe`, создать там `config.json` из встроенного шаблона (`agent_name` из hostname, токен-плейсхолдер), установить службу Windows (LocalSystem, автостарт) и открыть форму управления. При токене-плейсхолдере служба SHALL быть установлена, но не запущена.

#### Scenario: Чистая машина, запуск из чужого каталога

- **WHEN** пользователь запускает exe из каталога, отличного от `%ProgramFiles%\siren`, а служба не установлена
- **THEN** копия exe создана в `%ProgramFiles%\siren`, конфиг создан с `agent_name` из hostname, служба установлена, правило брандмауэра создано, форма открыта, служба не запущена (токен — плейсхолдер)

#### Scenario: Повторный запуск после самоустановки

- **WHEN** exe запускается повторно, а служба уже установлена
- **THEN** копирование, создание конфига и установка службы не повторяются; форма просто открывается

#### Scenario: Существующий конфиг не затирается

- **WHEN** при первом запуске `%ProgramFiles%\siren\config.json` уже существует
- **THEN** конфиг остаётся без изменений

### Requirement: Запуск с настроенным конфигом поднимает службу

Если при самоустановке конфиг уже содержит реальный токен (не плейсхолдер), служба SHALL быть запущена сразу, без участия пользователя.

#### Scenario: Перенос настроенной установки

- **WHEN** exe с настроенным конфигом рядом запускается на машине без службы
- **THEN** самоустановка завершается работающей службой

### Requirement: Повторный запуск обновляет установленного агента

Запуск exe иной версии, чем установленная копия в `%ProgramFiles%\siren`, при установленной службе SHALL работать как обновление: служба останавливается, копия exe заменяется, служба возвращается в состояние, в котором находилась до обновления.

#### Scenario: Обновление работающего агента

- **WHEN** пользователь запускает новый exe, а служба работает на старой копии
- **THEN** служба остановлена, `%ProgramFiles%\siren\siren.exe` заменён, служба запущена заново

### Requirement: Брандмауэр сопровождает жизненный цикл службы

Установка службы SHALL создавать программное правило брандмауэра «siren traps» (входящий TCP к exe агента); удаление службы SHALL удалять это правило. Повторная установка SHALL NOT создавать дубликат правила.

#### Scenario: Правило создаётся один раз

- **WHEN** служба устанавливается повторно (обновление, переустановка)
- **THEN** правило брандмауэра одно и указывает на текущий путь exe
