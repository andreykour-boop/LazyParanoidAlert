# Конфигурация

Все параметры `config.json`. Обязательные: `agent_name`, `telegram.token`,
`telegram.chat_id`, `aggregate_window_seconds` (при отсутствии ставится 300).
Незнакомые поля игнорируются; ошибки валидации называются по имени параметра,
агент с невалидным конфигом не стартует. Шаблон — `config.example.json`
в комплекте; кодировку держите UTF-8 (BOM допускается).

## Пример

```json
{
  "agent_name": "WIN-PC01",
  "profile": "desktop",
  "telegram": {
    "token": "123456:REPLACE-WITH-BOT-TOKEN",
    "chat_id": "-1001234567890"
  },
  "aggregate_window_seconds": 300,
  "allowlist": ["127.0.0.1", "192.168.1.10:22"],
  "name_map": {
    "192.168.1.10": "my-laptop"
  },
  "data_dir": "data",
  "log_level": "info",
  "log_file": "siren.log",
  "health": {
    "enabled": true,
    "check_hour": 9,
    "report_weekday": 1,
    "warn_pct": 10,
    "min_free_gb": 0
  }
}
```

Linux-агенту дополнительно нужен `sshd_unit`.

## Параметры

### `agent_name` (строка, обязателен)

Имя этой машины в алертах. Обычно совпадает с hostname.

### `profile` (строка, необязателен)

Профиль ловушек по умолчанию: `"desktop"` или `"server"`. Профиль
заполняет `traps`, явные записи в `traps` переопределяют его по порту.
Порты легитимного трафика локальной сети (SMB/RPC 445/135/139, доменные
53/88/389/464/3268) в профилях отсутствуют сознательно.

- `desktop` — общий набор + 80/443 (входящий веб на рабочей станции —
  аномалия);
- `server` — общий набор (на сервере 80/443 часто обслуживают реальные
  веб-интерфейсы).

Общий набор: 21 ftp, 23 telnet, 69 tftp, 2049 nfs, 3306 mysql, 5432
postgres, 1433 mssql, 6379 redis, 27017 mongodb, 5900 vnc, 5985/5986
winrm, 22 ssh, 3389 rdp.

### `traps` (список, необязателен)

Явный список ловушек (дополняет/переопределяет профиль):

```json
"traps": [
  {"port": 2222, "enabled": true, "emulator": "ssh"},
  {"port": 443, "enabled": false, "emulator": "http", "tls": true}
]
```

- `port` (1–65535) — слушаемый порт;
- `enabled` — ловушку можно выключить, не удаляя;
- `emulator` — протокол-имитация: `ftp`, `telnet`, `ssh`, `http`, `vnc`,
  `mysql`, `postgres`, `silent`;
- `tls` — обернуть эмулятор в TLS (самоподписанный сертификат создаётся в
  `data_dir`; уместно для 443).

### `telegram` (объект, обязателен)

- `token` — токен бота от @BotFather;
- `chat_id` — ID чата доставки (личный или группы; у групп обычно
  отрицательный);
- `api_url` (необязателен) — переопределение endpoint Bot API; для тестов и
  air-gapped интеграций.

### `aggregate_window_seconds` (целое, обязателен)

Окно агрегации повторных событий одного источника в секундах, должно быть
> 0. Значение по умолчанию, если поле отсутствует, — 300.

### `allowlist` (список строк, необязателен)

Источники, которые не алертятся. Формат записи:
`хост[/CIDR][:порт[,порт…]]`.

| Запись | Действие |
|---|---|
| `192.168.1.10` | гасит всё от этого хоста |
| `10.0.0.0/24` | гасит всё из сети |
| `192.168.1.10:22` | гасит только события порта 22: ловушку на 22 **и** реальные SSH-входы |
| `10.0.0.0/24:22,3389` | сеть, порты через запятую |
| `[::1]:22` | IPv6 с портами — в скобках |
| `::1` | IPv6 без портов — весь источник |

Правила:

- запись с портами **не** гасит событие, у которого порт не определён;
- сервисные порты дверей фиксированы: SSH — 22, RDP — 3389. Если sshd
  переведён на нестандартный порт, используйте запись без портов;
- типовой allowlist: `"127.0.0.1", "::1"` — свои проверки с той же машины
  в Telegram не попадают.

### `sshd_unit` (строка, Linux)

Имя systemd-юнита, чей журнал читает датчик SSH: `"ssh"` (Debian/Ubuntu)
или `"sshd"` (RHEL/CentOS).

### `name_map` (объект «IP → имя», необязателен)

Человекочитаемые имена источников в алертах; имеют приоритет над reverse DNS:

```json
"name_map": {"192.168.1.10": "my-laptop", "192.168.1.55": "office-nas"}
```

### `data_dir` (строка, по умолчанию `"data"`)

Каталог состояния агента: самоподписанный TLS-сертификат ловушек,
`health_state.json` сторожа.

### `log_level` (строка, по умолчанию `"info"`)

Уровень журнала: `debug`, `info`, `warn`, `error`.

### `log_file` (строка, по умолчанию `"siren.log"`)

Путь журнала агента. Пустое значение — stderr (полезно с
`-console`/systemd).

### `health` (объект, необязателен)

Сторож здоровья дисков. Отсутствие секции = значения по умолчанию
(включён, проверка ежедневно в 09:00, недельный отчёт по понедельникам).

```json
"health": {
  "enabled": true,
  "check_hour": 9,
  "report_weekday": 1,
  "warn_pct": 10,
  "min_free_gb": 0
}
```

- `enabled` — `false` полностью выключает сторож;
- `check_hour` (0–23) — час локального времени ежедневной проверки;
- `report_weekday` (0=воскресенье … 6=суббота) — день недельного отчёта;
- `warn_pct` (1–99) — порог свободного места в процентах от объёма тома;
- `min_free_gb` — абсолютный минимум свободного места в ГБ; 0 выключает
  абсолютный порог.

Срабатывает любой из порогов. Вне расписания смотреть здоровье:
`sudo /opt/siren/siren -health-report` (Linux) или секция «Диски» в пульте
(Windows) — оба варианта ничего не пишут и не отправляют.

## Изменение на лету (Windows)

Пульт управления читает и пишет этот же конфиг: сохранение проходит ту же
валидацию, при ошибке изменения не применяются. После сохранения пульт
предлагает перезапустить службу. На Linux конфиг правится вручную +
`sudo systemctl restart siren`.
